# Platform differences: Identify the API before copying examples

This page is an **entry-point index, not a version-pinned SDK tutorial**. When the user explicitly needs executable requests, inspect the project's existing SDK/model/API, invocation method, and current official documentation for the target platform first, then check schema subsets, tool rounds, image capabilities, and error/refusal paths; do not deploy based solely on field names here. The name `responses_format` is not a universal field in the OpenAI Responses API.

| Interface | Tool definition | Final structured response | References to check |
| --- | --- | --- | --- |
| OpenAI Responses API | Flat `type: "function"`, `name`, `description`, `parameters` in `tools`; configurable `strict` | `type: "json_schema"`, `name`, `schema`, `strict` within `text.format` | [function calling](https://developers.openai.com/api/docs/guides/function-calling), [structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) |
| OpenAI Chat Completions | `function: {name, description, parameters, ...}` wrapper in each `tools` item | `response_format: {type: "json_schema", json_schema: {name, schema, strict}}` | Same as above; **do not** place Chat's `response_format` in Responses' `text.format` location |
| Anthropic Messages API | Custom tools have `name`, `description`, `input_schema`; check conditions for `strict` support for strict input validation | `json_schema` in `output_config.format` | [define tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools), [structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) |
| Gemini API | Function declaration names, descriptions, and parameter schemas; outer wrappers vary by API | Interactions API uses JSON text configuration in `response_format`; `generateContent` uses configuration such as `response_mime_type` + `response_schema`; check the actual version | [function calling](https://ai.google.dev/gemini-api/docs/function-calling), [structured output](https://ai.google.dev/gemini-api/docs/structured-output), [migration guide](https://ai.google.dev/gemini-api/docs/migrate-to-interactions) |

**Specific differences:** OpenAI strict functions set `additionalProperties: false` on objects and list all properties in `required`; nullable values can represent business-optional fields. Other providers' constraints differ. Services support only subsets of JSON Schema; arbitrary standard JSON Schema cannot be sent unchanged across platforms. Anthropic tools' `input_schema` describes tool **inputs**, whereas `output_config.format` constrains the assistant's **final answer**; OpenAI tool parameters and `text.format` likewise have separate contracts. Do not equate "request JSON" with enabling strict structured output. [OpenAI strict mode](https://developers.openai.com/api/docs/guides/function-calling), [Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Gemini structured output](https://ai.google.dev/gemini-api/docs/structured-output).

For `gen_image`, the prompt describes the image; dimensions, quality, transparency, reference images, masks, etc. are carried by request parameters/inputs supported by the actual platform and model. Saying "transparent" in the visual description does not guarantee an alpha-channel file, and saying "edit image A" does not send image A. Compare generation/editing interfaces, valid parameter ranges, and output formats using the [OpenAI image prompting guide](https://developers.openai.com/api/docs/guides/image-prompting) and [Gemini image generation](https://ai.google.dev/gemini-api/docs/image-generation). When platforms migrate, update/validate specific API examples first; do not silently switch an old project to a new interface.

# 独立监督与原生 heartbeat

编排者创建或复用监督会话前读取；监督者开始工作时读取本文件及收到的任务上下文。监督是独立逻辑职责，不是额外管理层，也不意味着拥有工具未授予的强制权限。

## 启动合同

监督者须收到：

- 用户目标、可观察验收结果、明确不做及其他约束；
- 已同意、拒绝或尚未明确的授权；
- 编排者实际 agent ID；
- 唯一当前任务表的实际位置和访问方式；
- 集成 workspaceId、实际路径、分支及集成 / 最终验证 owner；
- 本监督流程，以及适用的项目要求。

独立 Paseo 会话不等于独立 Git worktree；监督者不写业务源码，可使用不会提前回收的合适 workspace。复用会话先确认适合当前任务，保留其他任务内容和资源。

监督者不负责日常派工，不直接改业务源码、不执行日常合并，不成为每次设计、提交或测试变更的审批人。

## 建立与停止定时监督

1. 在监督者自己的会话中发现并阅读 Paseo 原生 heartbeat 工具 schema。当前接口以 cron cadence 向调用者会话发送 prompt；不要假设存在目标 agentId 参数。
2. 按实际语义设置默认每 30 分钟触发一次的检查。若工具采用标准五字段 cron，`*/30 * * * *` 表示每小时第 0、30 分钟，不承诺“创建后恰好 30 分钟”；按当前工具确认时区，不猜字段或执行时刻。
3. 从实际返回核实创建成功，记录 heartbeat ID、所属会话和周期，并向编排者报告。仅创建了监督会话、工具请求失败或尚无确认时，不声称已建立定时监督。
4. 任务完成、取消或不再需要监督时，监督者删除自己的本任务 heartbeat，核实并报告实际结果，再按授权处理会话归档。不得顺手删除复用会话中其他任务的 heartbeat。
5. 删除失败或会话不可用时，记录 ID、所属会话及阻塞，让有权操作者处理，不假设归档会话自动停止定时器。

按当前工具的真实返回能力核实，不编造 heartbeat list / update 接口。不要假设编排者能代另一会话创建或删除 heartbeat。`schedule` 若每次新建 agent，不能冒充返回原会话的 heartbeat。

原生 heartbeat 不可用时明确报告监督能力限制；不得口头宣称“已安排定时监督”，也不自行搭建后台脚本或监控平台。继续其他不受影响的已授权工作。

## 每次只检查当前相关证据

按需读取：编排者近期决策与实际活动、唯一当前任务表、集成 diff、必要执行角色的进展，以及对应当前版本的验证结果。关注可合入交付是否积压，已完成且获准清理的 workspace 是否及时回收。不要把历史通过结果当成当前版本结论。

重点判断：

- 是否偏离用户目标、扩张范围，或有更简单的等效设计？
- 是否为了旧实现细节增加不必要兼容，或不断新增抽象、事实模型、配置和通用框架？
- 是否只增加局部通过数，却没有集成可用结果？
- 是否出现重复研究、反复封包、无价值审查或主控串行瓶颈？
- 多个角色是否被同一共享阻塞卡住，却仍在增加并行度？
- 是否误把真实产品缺陷当成旧测试问题，或反过来？
- 是否需要简化、调整任务边界，或只在局部重新设计？

监督不是重复所有测试或重做全仓审查。没有问题就简短说明，不为证明监督有效而制造问题。

## 纠偏与升级

发现问题时只给必要结论：

```text
证据：{{当前决策、diff、任务状态或验证结果}}
影响：{{对目标、授权、安全、复杂度或吞吐的具体影响}}
最小纠正动作：{{由谁停止扩张、先集成、缩小设计或调整分工}}
```

可以要求编排者停止非必要扩张、优先集成、缩小设计或调整分工；不要默认推翻正确实现、增加流程或要求全仓重审。

编排者必须处理具体意见：接受则说明如何落实并同步相关角色；不接受则给出简短事实依据；涉及用户目标、业务契约或授权冲突则向用户提出聚焦问题。

重大偏离未被纠正时，监督者须在自己的 Paseo 会话向用户明确报告，不能只藏在内部交付消息里。以事实说明未解决问题，不宣称具有未授予的强制管理权。

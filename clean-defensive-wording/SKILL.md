# 清理防御性描述

## 核心原则

- **直接陈述事实与明确边界**：写出系统实际做什么、测了什么、没测什么、在什么条件下失效；不写自我保护式的免责套话。
- **假设读者具备基本工程常识**：代码和环境状态会随时间变化、备份未演练恢复、文档只记录编写时现状，这些常识不在文内重复提醒。
- **区分“真实约束”与“防御性废话”**：
  - **保留**：具体技术限制（如“共享 Caddy，不能为单个反代停服”）、实际已测/未测范围（如“仅测内网 HTTP，未验外层 HTTPS”）、明确的系统行为（如“仅确保索引存在，不校验原图可下载”）、明确的安全或授权边界。
  - **清理**：抽象免责、推卸结论、常识性提醒、模糊对冲词（hedging）与重复强调“不等于/不代表”。

## 扫描方法（中英文检索）

对目标目录或文件同时执行中文与英文两套检索（如有需要可用 `--glob` 排除临时草稿目录）：

### 1. 中文检索

1. **高频防御词模式扫描**
   ```bash
   rg -n '(不代表|不等于|不能据此|不保证|不承诺|不作为|不算|无异机|未演练|需重新核实|另行核实|按需核实|会变化|以.*为准|仅供|不自动)' <目标路径>
   ```
2. **单字 `不` 兜底扫描**（很多隐蔽的防御性表述都带“不”字）
   ```bash
   rg -n '不' <目标路径>
   ```
   重点复核 `(不保证|不承诺|不冒称|不能作为|不是.*验收|不代表)` 等漏网表述，逐条区分是真实约束还是防御套话。

### 2. 英文检索（不区分大小写 `-i`）

1. **常见 AI 过渡填充、对冲词与免责套话扫描**
   ```bash
   rg -ni '(it is (important|worth) (to note|noting|mentioning)|keep in mind|please note|depending on|may vary|tends to|generally speaking|as a general rule|use at your own risk|no guarantee|not guaranteed|does not (guarantee|imply|represent)|for reference only|subject to change)' <目标路径>
   ```
2. **高频模糊情态词与副词兜底扫描**
   ```bash
   rg -ni '\b(typically|generally|usually|potentially|possibly|presumably|may|might|could|carefully|ensure|important|note)\b' <目标路径>
   ```
   重点复核没有对应硬性技术条件（如具体阈值、明确版本、明确错误码）的模糊修饰与抽象提醒。

## 改写对照

| 常见防御性写法 | 清理后写法 | 处理方式 |
| --- | --- | --- |
| `……，不代表已端到端验证 / 不能据此认定……` | `未做……端到端验收`（或直接删除，前文已写清范围） | 删推卸套话，保留具体未测项 |
| `观察窗未再出现，不保证根除` | `观察窗未再出现` | 删除“不保证……” |
| `64 MiB 内存容器，不作负载承诺` | `64 MiB 内存容器` | 删除“不作……承诺” |
| `服务运行状态在相关任务中核实` / `会变化，续做前需重新核实` | *（整句删除）* | 删除常识性提醒 |
| `归档校验已通过，未演练恢复` | `归档校验已通过` | 删除冗余“未演练恢复” |
| `**不是生产 SM-on 验收**` / `不是线上……联调` | `未验生产 SM-on` / `未做线上……联调` | 用平实“未验/未做”替代防御性否定 |
| `保证索引存在，不保证原图可下载` | `仅确保索引存在，不校验原图可下载` | 改写为客观的系统行为 |
| `It is important to note that X may fail if...` | `X fails if...` | 删除过渡填充，改为直接条件句 |

## 收尾核对

- **不误删事实**：确认真实的技术限制、安全边界与具体未验证范围完整保留。
- **链路与格式验证**：清理后检查 Markdown 链接（含锚点）无断链，再复跑一次中文/英文特征词扫描确认无遗漏。

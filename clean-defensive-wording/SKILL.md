# 清理防御性冗余（文档 · 代码 · 过度设计 · 测试）

## 核心原则

- **区分“真实边界”与“防御性冗余”**：
  - **文档**：只写系统实际行为、具体技术限制与已测/未测范围，删除抽象免责与常识提醒。
  - **代码**：在**信任边界**（外部输入、I/O、第三方响应）执行“解析而非校验（Parse, Don't Validate）”并**快速失败（Fail Fast）**；进入可信核心后信任类型与契约，删除吞错、推测性兜底与重复防线。
  - **架构与抽象（YAGNI）**：按已证实的需求做最小实现；不为“未来可能用到”提前造接口、配置面或兼容层。
  - **测试**：用线性、无分支的脚本验证**可观测的公共契约**；异常用框架断言，内部协作不用 mock，不测私有细节、不可能分支或 mock 本身。

## 一、文档、记忆与报告

### 保留 vs 清理
- **保留**：具体技术限制（如“共享 Caddy，不能为单个反代停服”）、实际已测/未测范围（如“仅测内网 HTTP，未验外层 HTTPS”）、明确的系统行为（如“仅确保索引存在，不校验原图可下载”）、明确的安全/授权边界。
- **清理**：抽象免责、推卸结论、常识性提醒（环境会变化、备份未演练、文档仅反映编写时状态）、模糊对冲词（hedging）与重复“不等于/不代表”。

### 扫描命令
```bash
# 中文高频防御词 + 单字“不”兜底
rg -n '(不代表|不等于|不能据此|不保证|不承诺|不作为|不算|无异机|未演练|需重新核实|另行核实|按需核实|会变化|以.*为准|仅供|不自动)' <目标路径>
rg -n '不' <目标路径>

# 英文填充、对冲与免责套话 + 模糊情态词兜底
rg -ni '(it is (important|worth) (to note|noting|mentioning)|keep in mind|please note|depending on|may vary|tends to|generally speaking|as a general rule|use at your own risk|no guarantee|not guaranteed|does not (guarantee|imply|represent)|for reference only|subject to change)' <目标路径>
rg -ni '\b(typically|generally|usually|potentially|possibly|presumably|may|might|could|carefully|ensure|important|note)\b' <目标路径>
```

### 改写对照
| 常见防御性写法 | 清理后写法 | 处理方式 |
| --- | --- | --- |
| `……，不代表已端到端验证 / 不能据此认定……` | `未做……端到端验收`（前文已写清则直接删） | 删推卸套话，保留具体未测项 |
| `观察窗未再出现，不保证根除` | `观察窗未再出现` | 删除“不保证……” |
| `64 MiB 内存容器，不作负载承诺` | `64 MiB 内存容器` | 删除“不作……承诺” |
| `会变化，续做前需重新核实` / `未演练恢复` | *（整句删除）* | 删除常识性提醒 |
| `**不是生产 SM-on 验收**` | `未验生产 SM-on` | 用平实“未验/未做”替代防御性否定 |
| `保证索引存在，不保证原图可下载` | `仅确保索引存在，不校验原图可下载` | 改写为客观的系统行为 |
| `It is important to note that X may fail if...` | `X fails if...` | 删除过渡填充，改为直接条件句 |

## 二、生产代码：防御性逻辑与过度设计

### 1. 防御性代码逻辑（保留边界，清理内部）
- **保留**：信任边界处的 schema/类型解析与校验、外部服务容错（明确的超时、重试、断路器、可预期的网络降级）、明确的权限与并发锁。
- **清理**：
  - **宽泛异常吞错**：`except Exception:` / `catch (e)` 后仅打日志并返回假值（`None`/`null`/`-1`/`[]`/`{}`），掩盖契约破坏并导致静默数据损坏（GIGO）。改为收窄异常类型或直接向上抛出。
  - **推测性 Fallback**：对已有 schema 或类型保证的字段补默认值（如 `createdAt ?? new Date()`、`userId || 0`）。改为直接读取，缺失即报错。
  - **不可达/冗余分支**：在可信核心内对同一不变量多层重复判空、判类型（`?.`、`!= null`、`isinstance`、`hasattr`），或为类型系统已排除的分支写静默 `default:`/`else` 兜底。改为边界一次解析，内部直接解引用或显式断言不可达。
  - **空桩与无意义包装**：空清理回调（`() => {}`）、只转发不增值的透传封装。直接删除。

### 2. 过度设计（Over-engineering / YAGNI）
- **保留**：确实存在多个实现/消费者的多态接口、明确要求的扩展点或跨边界契约。
- **清理**：
  - **单实现抽象与过早泛化**：只有一个实现类的 `Interface`/`ABC`/`Protocol`、只有 1–2 个分支却硬套 `Factory`/`Strategy`/`Registry`/规则引擎。直接内联为具体类或简单映射。
  - **未要求的配置面与别名映射**：需求未提的可选开关、环境变量、多套字段别名映射（alias map）、多层透传 `options` 对象。只保留规范契约。
  - **死兼容垫片**：为不存在或已迁走的内部调用方保留的旧字段兜底、双写适配、re-export 兼容层。直接删除并同步调用方。
  - **过度拆碎的微函数**：把十几行线性逻辑拆成多个只调用一次、徒增跳转与类型样板的私有函数。合并回清晰的单函数。

### 扫描命令
```bash
# 宽泛捕获 / 疑似吞错返回默认值
rg -n '(except\s*(Exception|BaseException)?\s*:|catch\s*\([^)]*\)\s*\{)' <代码路径>

# 疑似推测性兜底默认值（逐条核对是否位于信任边界）
rg -n '(\?\?|\|\|)\s*(\[\]|\{\}|""|'\'''\''|0|null|None|false|new Date|datetime\.now)' <代码路径>

# 内部冗余类型/空值守卫（对照调用链类型契约复核）
rg -n '(isinstance|hasattr|typeof\s+\w+\s*===|!==\s*(undefined|null))' <代码路径>

# 过度设计信号：抽象基类/工厂/注册表/别名兼容（核查是否仅有单一实现）
rg -n '\b(Abstract\w*|Base\w*|\w*Factory|\w*Registry|\w*Strategy|\w*Provider|Protocol|ABC)\b' <代码路径>
```

## 三、测试代码：不合理测试清理

### 保留 vs 清理
- **保留**：真正的外部边界替身（第三方支付/HTTP API、时钟/随机数）、真实历史 Bug 回归用例、使用框架原生机制的异常断言。
- **清理**：
  1. **测试控制流（Conditional Test Logic）**：测试内出现 `if`/`else`/`for`/`while`/`switch`，导致部分断言可能静默跳过。改为拆分为独立线性用例，或改用参数化测试（`pytest.mark.parametrize`、`test.each`）。
  2. **测试内手写 `try/catch`**：手动捕获异常容易在“未抛异常”时误通过。改为 `pytest.raises`、`expect().toThrow()`、`assertThrows`。
  3. **弱断言与松弛断言**：只测 `toBeDefined()`、`toBeTruthy()`、`is not None`、`len >= 0` 或 `if (res) { expect(res.id)... }`；改为断言精确输出、状态变化或错误类型/错误码。
  4. **过度 Mock 与“测 Mock 本身”**：对内部模块、工具函数或本地存储全量打桩，或断言“mock 返回了刚配置好的返回值”。删除内部 mock，改用真实实现或轻量内存 fake。
  5. **测私有实现与不可能分支**：断言私有字段、内部调用次数/顺序、大段脆性快照，或强行 mock 出现实中不会发生的内部异常只为凑覆盖率。改为只测公共契约与真实等价类。
  6. **同义反复与语言/框架自证测试**：照抄实现逻辑的断言、测试框架自带类型校验或简单 getter/setter 的无意义测试。删除。

### 扫描命令
```bash
# 测试中的条件分支与手写异常处理
rg -n '^\s*(if\s*[\(: ]|else\b|for\s*[\( ]|while\s*[\( ]|switch\s*\(|try\s*[:{]|catch\s*\(|except\b)' <测试路径>

# 弱断言 / 存在性敷衍断言
rg -n '(toBeDefined|toBeTruthy|not\.toBeNull|assert\s+\w+\s+is\s+not\s+None|assertTrue\()' <测试路径>

# 过度 Mock 信号（核查是否 mock 了内部模块）
rg -n '(MagicMock|monkeypatch|jest\.spyOn|jest\.mock|vi\.mock|Mockito\.when)' <测试路径>
```

## 执行流程与收尾核对

1. **定边界**：先判断目标属于文档、代码还是测试；若改代码，先标出信任边界与真实需求范围。
2. **扫描与分诊**：运行对应 `rg` 模式，逐条区分“真实约束/边界防护/必要抽象”与“防御性冗余/过度设计/不合理测试”。
3. **清理与验证**：
   - **文档**：检查 Markdown 链接与锚点无断链，复跑中英文特征词扫描确认无遗漏。
   - **代码与测试**：删除无用代码与死测试后，运行项目真实测试套件、类型检查与 linter，确认快速失败路径与核心契约全部通过；禁止通过删有效测试或放宽断言来通过校验。
